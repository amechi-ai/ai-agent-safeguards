# Contributing

This is an experimental community initiative. We welcome criticism, improvements to the behavioural protocol and technical requirements, reproducible tests, and reports of residual risks.

## Proposing changes

Open an issue or pull request describing the affected protocol clause, technical safeguard or test scenario. Explain the weakness, proposed correction, anticipated effect on legitimate work, and any limitations. Clearly distinguish proposed changes from executed tests and independent verification.

For experimental evidence, include the exact version or commit, environment, expected and observed results, and reproducible steps. Use isolated synthetic workloads and credentials. Do not test on real client systems, live third-party services or production agents without explicit authorisation.

Do not include secrets, client information, private infrastructure details or live incident payloads in public issues or pull requests. If a finding concerns a real system, use the affected provider's authorised vulnerability reporting process instead.

A passing reference-model test is not a claim of operational security. Preserve the distinction between behavioural compliance, host enforcement and observed effects. Do not mark implementation scenarios as passed without implementation evidence.

## Review and approval
Submit changes by pull request with the relevant clause, test and version references, expected and observed results, effects on benign work, and remaining risks. Disclose material AI assistance and conflicts. Independent review and explicit owner approval are required for substantive security or behaviour changes; editorial corrections receive proportionate review. Never approve or merge your own AI-assisted work through an autonomous agent. The founder retains release authority. See GOVERNANCE.md, VALIDATION_STATUS.md and SECURITY.md.

## Rights and contributions
Only submit material you are authorised to share. The proposed dual licence is conditional, not yet granted; see LICENSING.md. Do not include third-party material without verified rights, and do not assume a contribution is automatically relicensed. Sensitive reports should follow SECURITY.md rather than public issues.
